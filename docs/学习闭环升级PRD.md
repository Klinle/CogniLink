## 一、背景与问题

产品定位一句话：**把你上传的教材，变成可对话、可练习、可追踪的私人 CS 教练。**

当前版本已具备学习闭环的左半段（导入教材 → 对话理解 → 针对性练习），但存在三个断点，导致"教练"体验退化为"问答工具"：

| # | 断点 | 用户感受 | 数据表现 |
|---|------|---------|---------|
| 1 | 冷启动空白 | 新用户登录后 dashboard 全零、图谱全灰，不知道从哪开始 | 画像雷达图初始全零，首周流失集中在首次会话 |
| 2 | 练完即忘 | 答错的题没有下文，无法巩固；"错题本"只能靠手动收藏 | user_lab_submissions 有失败记录但无消费方 |
| 3 | 信任断层 | 回答标注 `[来源: 文档, 第N页]` 但只是纯文本，无法验证 | 溯源标注不可点击，无法回到原文 |

本次升级围绕这三个断点补齐闭环右半段（巩固、复习、计划），并在 M2/M3 深化练习与检索、扩展教学场景。

## 二、目标与非目标

### 2.1 目标（按里程碑）

| 里程碑 | 产品目标 | 北极星指标 |
|--------|---------|-----------|
| M1 补齐闭环 | 新用户 10 分钟内获得个性化画像；错题自动进入复习循环；回答可溯源验证 | 新用户诊断完成率 ≥ 70%；周复习队列完成率 ≥ 50%；溯源 chip 点击率可观测 |
| M2 深化 | 对话中无缝出题；code 题客观判分；检索质量可观测 | code 题沙箱判分覆盖率 ≥ 95%；检索零结果率逐周下降 |
| M3 扩面 | 目标驱动的学习计划；教师建班可用；移动端可安装 | 计划 7 日留存；班级作业完成率可见；Lighthouse PWA 达标 |

### 2.2 非目标（明确不做）

- 泛聊天能力增强——与通用 AI 助手重复的建设不做，只做与个人学习资产（文档/图谱/画像/错题）绑定的能力。
- 多租户 SaaS、计费、账号体系重构。
- 社交功能（学习社区、动态流）——班级空间仅覆盖"教师-学生"教学关系。
- 前端整体重构——工程项按任务书 §六 并行推进，不作为产品需求。

## 三、用户与场景

### 3.1 角色

| 角色 | 典型画像 | 核心诉求 | 本次覆盖 |
|------|---------|---------|---------|
| 备考学生（主） | 大二~大四 CS 专业，期末/考研/面试备考，有教材 PDF | 快速定位薄弱点、针对性刷题、考前复习不遗漏 | M1 全部、M2 沙箱/面试 |

```
                                   │
画像更新 ── 图谱点亮 / 雷达图变化 / 弱点驱动下一轮出题
```

## 五、M1 详细需求

### 5.1 T3 引用溯源跳转

**用户故事**：作为备考学生，当 AI 基于我的教材回答时，我希望点一下来源就能看到教材原文对应页，以便确认 AI 没有编造、并顺势精读上下文。

#### 交互定义

1. **来源 chip 展示**
   - 命中知识库的 assistant 消息，在正文下方渲染一行来源 chip（样式延续粗犷卡通纸张风格，形似索引标签）。
   - 每个 chip 文案：`文档名 · 第N页`；无页码时仅显示文档名。
   - 去重规则：按 `(document_id, page_number)` 去重；最多显示 **4 个** chip，超出折叠为 `+N`，点击展开全部。
   - 排序：按检索得分顺序（即后端返回顺序）。
   - 未命中知识库（sources 为空）时**不渲染**任何来源区域，不显示"无来源"占位。

2. **点击行为**
   - 点击 chip 打开**文档预览弹层**（不离开当前对话），弹层标题为文档名，右上角提供"在知识库中打开"跳转 `/knowledge` 的入口。
   - PDF：iframe 加载 `/{id}/file#page=N` 直接定位页。
   - 文本/Markdown：加载 `/{id}/content` 对应分页，并高亮命中 chunk 的首行（可行则做，不可行降级为定位到页首）。
   - 性能口径：点击后 **3 秒内**看到目标页内容（弹层立即出现，内容区可有加载态）。

3. **边界与降级**

| 场景 | 行为 |
|------|------|
| 来源文档已被删除 | chip 置灰 + tooltip "文档已删除"，不可点击 |
| 文档无权限（非本人且非 shared） | 后端不返回该 source，前端无感知 |
| 页码缺失（纯文本无分页信息） | chip 只显示文档名，点击打开文档第 1 页 |
| 弹层加载失败 | 弹层内显示重试按钮，不阻塞对话 |
| 移动端窄屏 | 弹层全屏化，返回手势/按钮关闭 |

#### 埋点

- `source_chip_impression`（消息级，含 chip 数）
- `source_chip_click`（含 document_id、page_number、消息内 chip 序号）

#### 验收标准

- Given 提问命中知识库，When 回答完成，Then 消息底部出现去重后的来源 chip，数量与 `data.sources` 一致（≤4 + 折叠）。
- Given 点击一个 PDF 来源 chip，When 弹层打开，Then 3 秒内看到对应页码内容。
- Given 提问未命中知识库（如闲聊），Then 不出现来源区域。
- Given 来源文档已删除，Then chip 置灰不可点击且有提示。

### 5.2 T1 诊断式 Onboarding

**用户故事**：作为新用户，我希望第一次登录时用几分钟告诉系统我的目标和水平，以便 dashboard、图谱和练习从第一天起就是"为我定制"的，而不是一片空白。

#### 流程定义（三步向导，新页 `/onboarding`）

**触发**：登录后 `onboarding_completed = 0` 时由 dashboard 重定向进入；老用户（升级前注册）视为已完成，不触发，但 dashboard 提供"学习力诊断"常驻入口可主动进入。

**Step 1 · 选主攻领域**（单选）
- 六大领域卡片（programming/dsa/organization/os/network/database），各配一句白话描述与代表知识点。
- 单选。选择仅影响本次诊断出题领域与 dashboard 默认推荐，不限制后续跨领域学习。
- 底部次要链接："跳过，稍后再说"（三步全程可用，见下）。

**Step 2 · 准备学习资料**（二选一，可都不选）
- 选项 A：上传我的教材（复用现有上传组件；上传后立即进入 Step 3，解析在后台进行，不阻塞诊断）。
- 选项 B：先用内置知识库（默认勾选；说明内置 41 个知识节点覆盖六领域）。
- 文案明确 local-first 承诺：文档只存本机部署的数据库、嵌入可全本地。

**Step 3 · 10 题诊断测验**
- 题目来源：预置诊断题库（`labs.tag = 'diagnostic'`），取所选领域 10 题；题型为 quiz/judge/match 等客观题（不含 code 题，控制时长）。
- 展示：进度条（3/10）、可上一题修改、不计时（降低压力）、复用 exercise-renderer。
- 提交后立即出结果页：各知识点对错分布、雷达图首次点亮动效、按钮"进入我的学习舱"（dashboard）。

#### 画像初始化规则

- 按题目关联的 `node_id` 聚合正确率，写入 `user_knowledge_states.proficiency` 初值。
- 节点正确率 ≥ 0.8 → 直接点亮（`is_lighted = 1`）。
- 未覆盖到的节点保持默认值，由后续练习补全。
- 诊断可重复进行（入口在 `/profile`），重测结果**只升不降**已点亮状态（避免一次失误熄灭已掌握节点），proficiency 取新值。

#### 跳过与中断

| 场景 | 行为 |
|------|------|
| 任一步点"跳过" | 标记 `onboarding_completed = 1`（含跳过标记），进 dashboard；dashboard 显示"完成学习力诊断"引导卡片直到实际完成一次诊断 |
| 中途关闭页面 | 已选领域暂存（localStorage），下次进入从中断步骤继续 |
| 答题中断 | 已答题目暂存，24h 内有效 |

#### 埋点

漏斗：`onboarding_enter → step1_done → step2_done → quiz_start → quiz_done / skip(step)`。目标：整体完成率 ≥ 70%，需可按步骤定位流失。

#### 验收标准

- Given 新注册用户首次登录，Then 自动进入 `/onboarding` 且不可直接访问 dashboard（地址栏直入 dashboard 会被重定向回）。
- Given 完成 10 题诊断，Then `/profile` 雷达图非全零、正确率 ≥ 0.8 的节点在 `/graph` 已点亮。
- Given 在 Step 1 点跳过，Then 进入 dashboard 且看到常驻诊断引导卡片。
- Given 升级前的老用户登录，Then 不触发向导。

### 5.3 T2 错题本与间隔重复

**用户故事**：作为备考学生，我希望答错的题被系统记住并在合适的时间提醒我重做，直到真正掌握，以便考前不留死角。

#### 入队规则

| 规则 | 定义 |
|------|------|
| 入队来源 | 题库提交（`/labs/{id}/submit`）与动态题评测（`/evaluate-dynamic`）的**未通过**结果；后续 T4 会话内出题、F1 闪卡沿用同一入口 |
| 未通过判定 | code 题：score < 60；客观题：任一小题答错 |
| 去重 | 同一题（lab_id 或题目内容哈希）已在队列中未毕业时，不重复入队，仅 `wrong_count + 1` 并重置调度 |
| 快照 | 入队时保存题目完整快照（content/answer/explanation），原题被删除或修改不影响复习 |
| 静默性 | 入队不打断当前流程，仅在评测结果区轻提示"已加入复习队列" |

#### 复习调度（对用户隐藏算法细节）

- SM-2 简化：答题质量隐式映射——**答对 = 4，答错 = 1**（不做主观自评，降低操作成本）；连续 3 次答对毕业出队。
- 界面语言用人话："下次复习：明天 / 3 天后 / 已掌握，移出队列"，不暴露 ease factor 等术语。
- 每日复习上限默认 **30 题**（超出顺延），防止积压劝退；上限值预留设置项。
- 提供"我已掌握"手动毕业与"移出错题本"删除操作（二次确认）。

#### 页面定义

**Dashboard 卡片**："今日待复习 N 题"，N > 0 时高亮并直达 `/review`；N = 0 且队列非空显示"今日复习已清，下次复习 X 天后"；队列为空显示引导去练习。

**`/review` 复习页**：
- 逐题模式：一次一题（复用 exercise-renderer），提交后立即显示对错、解析、下次复习时间，按钮"下一题"。
- 顶部进度：`今日 3/12`；完成全部后出结算页（今日答对率、连续复习天数）。
- 侧栏（桌面端）：错题本全量列表，按领域/状态筛选，可查看快照与手动操作。

#### 边界

| 场景 | 行为 |
|------|------|
| 复习中答错 | 重置连续答对计数，间隔回到 1 天，`wrong_count + 1` |
| 队列积压 > 100 题 | dashboard 卡片提示"建议先集中清理"，`/review` 提供按领域批量"我已掌握" |
| 同一题当日既在复习队列又被主动练到且答对 | 计为一次成功复习（避免重复劳动） |

#### 埋点

`review_enqueue`（含来源）、`review_session_start / done`、`review_answer`（对错）、`review_graduate / manual_graduate / remove`。指标：周复习队列完成率 ≥ 50%。

#### 验收标准

- Given 练习答错一题，Then 复习队列出现该题且再次答错不产生重复条目。
- Given 复习中答对，Then 下次复习时间按 1 → 3 → 7 天（默认参数）拉长；连续 3 次答对后该题显示"已掌握"并出队。
- Given 今日队列 12 题完成，Then 出结算页且 dashboard 卡片归零。
- Given 原题被管理员删除，Then 复习页仍可用快照正常作答。

### 5.4 F1 知识闪卡 + Anki 导出（M1 末评估随发）

**用户故事**：作为自学者，我希望把教材要点变成一问一答的闪卡加入每日复习，并能导出到 Anki 延续已有习惯。

- 生成入口：知识节点详情页"生成闪卡"（LLM 从节点关联 chunk 提炼 5~10 张问答卡，用户可勾选保留）；对话回答"存为闪卡"。
- 闪卡进入 T2 复习队列，作为独立 `source_type = flashcard`，复习交互为"看正面 → 自评 记得/模糊/忘了"（映射质量 5/3/1——闪卡无客观判分，此处保留轻量自评）。
- 导出：错题本页"导出 Anki（.apkg）"，含全部闪卡与错题（错题转为问答形式）。
- 验收：生成的闪卡可编辑后入队；.apkg 可被 Anki 正常导入。

## 六、M2 需求（中等详度）

### 6.1 T4 会话内出题

- **行为**：对话中出现练习意图（流水线已识别 `practice_request`）时，不再返回纯文本题目，而是在聊天流内渲染互动练习卡片（复用 exercise-renderer），提交即评测、答错自动入 T2 队列。
- **关键规则**：
  - 知识点定位：从改写后查询提取节点名匹配图谱；无匹配时取用户最弱节点并在卡片头部说明"根据你的薄弱点出题：XX"。
  - 一次最多出 3 题（用户明确说"来 5 道"时上限 5，超出提示去 `/practice`）。
  - 卡片在历史消息中保持可交互（未做的题回滚可做），已提交的显示结果态。
  - 降级：出题失败时回退为文本说明 + `/practice` 直达链接，不静默失败。
- **验收要点**："给我出两道装饰器的题" → 聊天流出现 2 张卡片 → 提交出分与解析 → 错题入队；意图误判为出题时（实际是概念提问）可通过卡片外的常规回答兜底（流水线保持正常应答文本 + 卡片并存）。

### 6.2 T5 Pyodide 代码沙箱

- **行为**：code 题在浏览器 WASM 内真实执行测试用例，客观判分（占 70%）+ LLM 代码质量讲解（占 30%）；断网时仍可判对错。
- **产品口径**：
  - 首次使用懒加载 Pyodide（约 10MB），显示一次性加载进度与"仅首次需要"说明；加载完成本地缓存。
  - 死循环/恶意代码：Worker 5 秒超时熔断，界面提示"执行超时，检查是否有死循环"，页面不卡死。
  - 沙箱不可用（老浏览器/加载失败）：静默回退纯 LLM 评测（现状），结果区标注"AI 评测"与"沙箱实测"来源徽标以示区别。
- **验收要点**：断网可判分；超时不影响页面；两种评测来源有可见区分。

### 6.3 T6 检索质量看板（admin）

- **行为**：每次 RAG 检索异步落日志；`/admin` 新增"检索质量"页：命中率趋势（7/30 日）、零结果查询 TopN（一键复制，用于补充知识库）、领域/意图分布。
- **产品口径**：日志保留 90 天；对话时延不受影响（异步写入，失败不报错）；查询文本属用户数据，看板仅 admin 可见。
- **验收要点**：能回答"哪些问题在知识库里查不到"；流水线迭代前后命中率可对比。

### 6.4 M2 推荐功能池项

| 项 | 一句话定义 | 验收要点 |
|----|-----------|---------|

## 八、全局产品规则

1. **视觉与文案**：延续新粗犷卡通纸张风格与大眼睛大脑 Logo 体系；新页面（onboarding/review）沿用像素风卡片语言。系统文案口吻 = 当前激活导师人设（幽默/学术/教练），默认通用语气；算法概念一律说人话（"下次复习：3 天后"而非"ease factor 2.5"）。
2. **Local-first 承诺贯穿**：所有新功能不得引入"必须上传数据到第三方"的路径；闪卡生成、诊断评分等 LLM 调用沿用用户自带 Key 或本地模型；F5 导出是承诺的兑现。
3. **降级矩阵**（新功能必须逐项核对）：

| 缺失条件 | 必须保证 |
|---------|---------|
| 无 API Key | 诊断（预置题+本地判分）、复习、溯源跳转全部可用；仅生成类功能提示配置 Key |
| 本地嵌入不可用 | 明确报错并指向设置页（现状已实现），不静默降级 |
| 断网 | M2 起 code 判分可用；M3 起复习可用 |
| 知识库为空 | 对话正常（无溯源）、练习走内置题库，各页空状态给"去上传"引导 |

4. **权限基线**：所有新 API 沿用 `get_current_user` 依赖链；涉及跨用户数据（T8）交付必含权限专项测试（参照 test_api_security.py 模式）。

## 九、数据与埋点汇总

- 新增埋点前缀：`onboarding_*`、`review_*`、`source_chip_*`、`chat_exercise_*`(T4)、`sandbox_*`(T5)、`plan_*`(T7)。
- 埋点仅落本地库（沿用 local-first），admin 看板消费；不接第三方分析。
- 指标看板最小集（admin）：诊断漏斗、周复习完成率、溯源点击率、检索命中率——M1 交付时至少以 SQL 可查，T6 交付后图形化。
